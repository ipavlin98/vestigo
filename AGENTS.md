# Vestigo

Latin for "I track down"; formerly sfs ("super fast search"). A Listary-style file launcher for Windows: global search window, Explorer and file-dialog integration, instant NTFS index. Rust + GPUI from gpui-unofficial 1.25.3 (vendored in `vendor/gpui` and `vendor/gpui_windows`, see GPUI patches).

## Developer note
Ambitious ideas, simple systems, obvious-feeling software. Don't preserve complexity because it exists; don't add machinery because it looks impressive. Understand the real constraint, then fight for the smallest model that makes correct behavior unsurprising. "Measure twice, cut once" + YAGNI. Fight scope creep. Honor dev intent minimally and realistically.

Rules serve their intent, not themselves. A required check runs only where it can catch something in this change: a change that can't differ between themes isn't shot in the second theme, a change that can't touch the scan, cache or search isn't speed-tested. Skip such a check and say so in one line in the report. When a rule plainly doesn't fit the situation, follow its intent and tell the user which rule and why.

Speed is the product. Indexing and search must stay instant; a change that slows them down is a regression even if it adds a feature.

No flicker, ever. Flicker breaks immersion and is a bug of the same rank as a crash, never polish. Every frame shows a complete state: never a blank, placeholder, half-loaded or stale-geometry frame between two complete ones. Keep the previous content on screen until the next is fully ready (data loaded, images decoded off the UI thread) and swap it in one frame; a window or panel appears only with its first frame painted; nothing hides and reappears because of a transient state (a selection passing over a row it doesn't apply to, a reload). Fix the cause (state model, ordering), never mask it with delays. Any change to what is shown while the user moves, types, scrolls or switches is reviewed for flicker in the code before reporting; a sandbox check for it follows Agent UI checks (only when the user asks, otherwise offered).

## Build and run
`cargo` is on PATH; call it directly.
- `cargo build`: debug build, `target\debug\vestigo.exe`.
- `cargo fmt --all` + `cargo clippy --all-targets -- -D warnings`: lint. Non-zero = unfinished work.
- `cargo test`: unit tests. No real windows, input, registry, drives or user data.
- `cargo test --release system_drive -- --ignored --nocapture`: speed test on the real `C:` (MFT scan, cache save/load, one search). `cargo test --release content_speed -- --ignored --nocapture`: the content index of `C:` in a temp folder, sweep and search timings. Both need administrator rights: run them from an elevated shell.
- Task fully done → lint and `cargo test` once each. Not after intermediate edits. Standing requirement.
- No release builds (`cargo build --release`) unless the user asks; releases are built by GitHub Actions.
- Running the app: one instance only; starting `vestigo.exe` again toggles the running instance's window. It asks for elevation at start (UAC). `vestigo.exe --quit` quits the running instance cleanly, elevated or not (`taskkill` can't stop an elevated one from a non-elevated shell); a running instance locks the exe, so quit it before a rebuild. Ask before quitting an instance the user is working with, unless they allowed it.
- Personal rules for one machine (no UAC prompt, relaunching the app after every build) go in `CLAUDE.local.md`, which git ignores.

## GPUI patches
GPUI comes from [gpui-unofficial](https://github.com/gpui-archipelago/gpui-unofficial) 1.25.3 (GPUI of Zed 1.25.3 on crates.io). Two of its crates are vendored: `gpui-unofficial` in `vendor/gpui` and the Windows backend `gpui-windows-gpui-unofficial` in `vendor/gpui_windows` (crates.io sources; `vendor/gpui` without examples and test fonts), wired in through `[patch.crates-io]` in `Cargo.toml`. `main.rs` creates the Windows platform itself (`gpui_windows::WindowsPlatform`, `Application::with_platform`), so no other backend is built. As in GPUI 0.2.2, Vestigo keeps grayscale text antialiasing (`TextRenderingMode::Grayscale`; upstream uses ClearType in opaque windows) and no frame limit for inactive windows (`inactive_frame_interval: None` in `ui::popup_options` and the app window: the card, menus and docked search window animate without focus). Upstream now snaps layout and paint bounds to device pixels itself (an SVG's bitmap size included, which retired the old icon bitmap patch). Each patch is listed here; keep the rest of the crates as published.
1. **Pixel-fitted icons.** Before rasterizing, `vendor/gpui/src/svg_renderer/hint.rs` moves straight horizontal and vertical segments so their whole pixels are solid (a pixel centre for lines 1-2 px wide, a pixel edge for 2-3 px and fills) and moves every other point in proportion between them, like font hinting; stroke widths stay. Snapping each line on its own broke symmetry (the stem of `COPY_NAME` landed a pixel off the middle of its serifs), so, like font hinters, the fitter first snaps the axis between the outermost lines (a pixel centre when a line 1-2 px wide lies on it) and places every pair of equal mirrored lines at a whole number of pixels from it; lines without a mirror image snap on their own (`placed`). Zero-length segments (the closing `z` of a circle or a path that ends where it starts) are not stems. Only SVGs with `shape-rendering="crispEdges"` are fitted (all of `assets`); anything else, or anything but solid paths, goes to resvg as before (`icon_mask` in `vendor/gpui/src/svg_renderer.rs`). Exported as `gpui::svg_icon_mask` for tests. Tests: `icon_lines_land_on_whole_device_pixels_at_any_scale`, `closed_curves_stay_centered_after_pixel_fitting`, `stem_stays_centered_between_mirrored_lines_after_pixel_fitting` in `src/assets.rs`.
2. **Frames over translucent fills.** The quad shader (`quad_fragment` in `vendor/gpui_windows/src/shaders.hlsl`) blends a border into its background in premultiplied alpha. Upstream lerps straight colors, so where a frame meets a translucent fill (the clear end of the picker's alpha bar) its anti-aliased edge took the fill's RGB at full weight and the curve came out dark and broken. Shader only: no automated test, check by eye.
3. **Window corners cut once.** `Window::cut_corners(bounds, radii)` (`vendor/gpui/src/window.rs`) records a `CornerCut` in the scene (`vendor/gpui/src/scene.rs`); after every batch the DirectX renderer (`draw_corner_cuts` in `vendor/gpui_windows/src/directx_renderer.rs`) draws it with a blend that multiplies the finished frame (color and alpha) by the rounded rectangle's coverage (`corner_cut_*` in `vendor/gpui_windows/src/shaders.hlsl`, module `corner_cut` in its `build.rs`). Upstream only has rectangular content masks, so a window's rounded edge came from each element rounding itself, and wherever two antialiased edges met (a panel and the hover fill of a caption button in its corner) the lower fill bled through as a light fringe. In Vestigo every window root goes through `ui::window_shape`, and nothing inside rounds itself to a window corner. Shader only: no automated test, check by eye.
4. **Tasks during modal loops.** `run_foreground_task` in `vendor/gpui_windows/src/platform.rs` clears the dispatcher's "wake message posted" flag before it runs tasks, so a task that runs a modal loop (dragging a result out with `SHDoDragDrop` from `ui::perform`) no longer blocks every other task until it returns: tasks dispatched meanwhile post a new wake message that the modal loop dispatches, as with GPUI 0.2.2. Without it, events from the watch and index threads, icon loads and searches waited for the drop. No automated test (the Windows dispatcher only).
5. **Morphs (experiment).** `Window::paint_morph(shapes, smoothness)` (`vendor/gpui/src/window.rs`) adds a `Morph` primitive to the scene (`vendor/gpui/src/scene.rs`, its own batch kind in draw order): up to `MORPH_SHAPES` rounded rectangles with their own colors, melted on the GPU by `morph_fragment` (`vendor/gpui_windows/src/shaders.hlsl`): the shapes' signed distances join through a polynomial smooth minimum whose weight also mixes their premultiplied colors, and coverage divides by the field's screen-space gradient so the edge stays one pixel wide in the bridges. `Window::paint_morph_shadow` casts the surface's shadow like a CSS box shadow (offset, spread, blur), kept outside the surface itself so it can lie under a translucent one (`Morph::casts` marks a shadow, so a blur of 0 stays one): a single shape's is the true gaussian of a rounded rectangle, the same picture `window/shadow.rs` paints on the CPU, so it can hand over to a shadow window without a jump (`blurred_shape`); melted shapes have no exact form and use a gaussian across the distance field. Pipeline `morphs` in `directx_renderer.rs`, module `morph` in `build.rs`. Demo: `vestigo.exe --morph` (`src/morph.rs`, a standalone process with closed-form springs). Shader only: no automated test, check by eye.
6. **Hidden windows placed at creation.** A window opened with `show: false` takes its placement at once with `SW_HIDE` (`WindowsWindow::new` in `vendor/gpui_windows/src/window.rs`), and the first activation no longer re-applies a windowed placement (`set_window_placement`). Upstream left a hidden window at `CW_USEDEFAULT` until its first activation, so the Vestigo window had to be activated on its first show: that took the focus from the search bar (which then hid) and moved the window after the bar-to-window transition had read its bounds, so the first transition after a cold start never ran. Maximized and fullscreen states set while hidden are still applied on the first activation. No automated test (Win32 placement).
7. **Frames on demand.** Upstream's vsync thread invalidated every window, hidden ones included, on every vsync, so the UI thread woke at the display's refresh rate (164 Hz on the dev machine) times the window count even with nothing to draw. Now each window has a `FrameRequest` (`vendor/gpui_windows/src/vsync.rs`) shared with the vsync thread, which sleeps on a condition variable until some window asks and then invalidates only the windows that asked. Windows implements GPUI's `frame_waker`/`schedule_frame` with it (the core already wakes the platform when a window gets dirty, gets next-frame callbacks or defers a frame); a draw deferred by the draw coordinator or by GPUI's re-entrancy guard (`draw_in_progress` in `vendor/gpui/src/window.rs`) asks again, so does a window restored from minimized, and Direct Manipulation keeps asking while a touchpad gesture runs or glides (`moving` in `direct_manipulation.rs`), since its viewport is updated only while drawing. No automated test (the vsync thread and Win32 paint loop).
8. **`WM_PAINT` validated with `BeginPaint`.** `handle_paint_msg` (`vendor/gpui_windows/src/events.rs`) wraps the draw in `BeginPaint`/`EndPaint` and answers `WM_ERASEBKGND` itself (DirectX draws every frame whole). `ValidateRect` alone left a hidden layered popup (the card) with a pending repaint it could never clear: Windows dispatched `WM_PAINT` to it about 200 000 times a second, a whole core busy while Vestigo sat idle. No automated test (Win32 paint loop).
Patches 1 and 4 come from traydex (`vendor/gpui`, `vendor/gpui_windows` there; the fitter matches its symmetric version).

## Architecture and code rules
Standing requirements for all new code. Feature works but breaks rules = not done. Rule in the way → propose architecture change first, no workarounds.

### Layers
- `index`: the file index. No UI knowledge.
  - `volume`: one drive (or an extra folder, `Volume::folder`). Nodes in a `Vec`, names in two string arenas (original + lowercase), parent links by node index, `ids` maps NTFS file reference numbers to nodes; sizes, modification times and the hidden flag live in parallel arrays beside the nodes, not in `Node`. `Builder` (`volume/builder.rs`) links records that arrive child-before-parent; `Family` (`volume/family.rs`) is a children-by-folder snapshot for reading details. `volume/scan.rs`: the search scan (`Volume::find`: one pass per chunk scores names, checks scopes, exclusions and path terms with one ancestor walk per parent, counts facets and keeps the best `limit` matches). `volume/folders.rs`: folders by path (`locate`, remembered per volume and rechecked against the path), subtree tests, the Start Menu fill. Exclusion rules (`$Recycle.Bin`, `System Volume Information`, `Windows\WinSxS`) live in `Volume::inherited`; unresolved parents make orphans. Excluded and recycled are inherited flags: journal changes go through `Volume::apply`, which recomputes them once per batch for the subtrees of moved folders. Replaced names and removed nodes count as waste; past 25 % (and 8 MiB) the drive thread swaps in `Volume::compacted`. A built volume keeps an eighth of headroom in every array and grows by an eighth (`volume/storage.rs`: `fit` in `Builder::finish`, `room` on journal inserts), never doubling: an index loaded at its exact size used to double every array on the first new file. `Volume::apply` also records `Edits` (nodes changed, and copies of nodes as they were before a rename, move or removal) for the content index.
  - `ntfs`: `Journal` opens the volume, `scan` enumerates the MFT (`FSCTL_ENUM_USN_DATA`), `watch` follows the USN journal and applies changes in batches under one write lock.
  - `details`: sizes and dates, read in the background after a scan (one folder listing per directory, in parallel, applied in chunks under short write locks) and refreshed for files the journal touched.
  - `cache`: binary snapshot per drive in `%LOCALAPPDATA%\Vestigo\index\<letter>.bin`, with the journal checkpoint and the details. It keeps visible entries and Recycle Bin contents (so a restored folder keeps its children), not other excluded folders or orphans. Startup loads it and replays the journal from the checkpoint; a stale or foreign checkpoint means a full scan. Saved on quit (`Shell`'s `on_app_quit`, which also runs when Windows ends the session; GPUI exits the process right after it) and while running only once the journal has filled half its size since the last save (`SAVE_SHARE` in `index/drive.rs`), so after a crash the journal still reaches back to the cached checkpoint without rewriting the whole cache every few minutes.
  - `walk`: fallback for non-NTFS drives and runs without administrator rights (no live updates); also walks extra folders (every 30 min).
  - `facets`: counts for the app window sidebar and date menu. `Facets::sorter` narrows the matches by the chosen kind and period and counts every kind and period, each cross-filtered by the other choice; kinds go through `search::Kinds` (one suffix lookup per dot), inside the search scan's chunks (`Sorter::sort` per match).
  - `Index`: all volumes, one thread per drive or extra folder; only that thread writes its volume. `search`/`search_with` (with facets) read. `Ranking` holds excluded, high and low priority folders and hidden-last; `restart`/`rebuild` bump a generation so stale threads stop. Threads report `Update::Contents` (results may change: scans, details, every journal batch) or `Update::Count` (only a count, from the content index). The drive thread (`index/drive.rs`) resumes the journal only from a checkpoint the journal still holds (`ntfs::holds`, from `FirstUsn`: `LowestValidUsn` stays 0 while old records are purged); when reading it fails mid-session (wrapped, deleted, recreated) it reads the MFT again (at most once per `RESCAN_PAUSE`) and keeps watching, never leaving a stale volume.
  - `content`: full-text search over file contents, off by default (`IndexOptions::full_text`), no thread or file while off. `Content` holds the `Library` behind one lock; the coordinator thread (`Index::run_content`, started and stopped by `Index::full_text`, run ids instead of a flag) is its only writer. Files come from the built `Volume`s only (`Volume::documents`, `CONTENT_NOISE`); `docs::reconcile` is the pure diff into add, update, remove and moved (same name, size and date: only the path changes), run at most every 2 s after `Content::touch` (a journal batch whose `Edits` can change the documents, `Content::note` + `Volume::edits_documents`: a document-format file outside the noise added, written, renamed, hidden or removed, or a folder renamed or moved; a folder walk; a ranking change; never journal noise like logs and caches, which used to reread every file name every 2 s on a busy system drive) and only while the queue is empty and every volume has its details. Text is extracted out of process: `worker::Extractor` feeds `vestigo.exe --extract` (`extract.rs`: formats, encodings, whitespace collapsed, limits) through a `Pipe` from the `Spawn` closure `main.rs` passes to `Index::extracting` (`platform/worker.rs`: restricted token, Low IL, job object with a memory limit); 30 s of silence or a crash restarts it, the files in flight then go one by one and the one that kills it again is `Failed` until its size or date changes. `store.rs`: `blocks.bin`, zstd frames of about 64 KB with a 256 byte overlap (the frame table lives in `docs.bin`, the file only grows, a header holds the epoch); `grams.rs`: trigram keys to block lists: `grams.bin` plus spilled runs (`run-N.bin`, same format, merged into it) on disk and the delta in memory (sharded, saved to `grams.delta`); `docs.rs`: `docs.bin`, the atomic commit point (documents, blocks, generation, commit number, store length); `library.rs`: packing batches, saving, rebuilding the grams from the store, compaction past 25 % and 8 MiB of waste. A store longer than the commit is cut, stale or missing grams are rebuilt from the store, a foreign `docs.bin` or store means a full reindex; format change → bump the `MAGIC`. `query.rs`: terms → candidate blocks (`Grams::candidates`) → documents → cheap filters and rank by `Sieve` → exact check in rank order in batches (`sift`, per-thread buffers from `store::with_scratch`, never a `Vec` per block) → snippets for the shown hits only. Past the first `limit` the count goes on within `COUNT_BUDGET`, then it reads `Listed::AtLeast`. Text keeps its original case and is folded while checking (`search::fold`: length-preserving for ASCII, Cyrillic and common punctuation, `to_lowercase` for the rest).
  - `lookup`: `Index::search_until`. A query with a place (`\sfs\src`, `D:\work`) resolves it to folders by exact names (`Volume::folders_at`); alone it lists the contents of the one folder (`Volume::contents`, folders first, `Listed::Contents`), the folders when the path names several, or the parent's children matching the unfinished last name; with other words it searches the folders' subtrees (`Area` in the scan).
- `search`: query parsing, name scoring, highlights. Pure. `syntax`: tokens, `date:`/`size:` values, `Clock`, `Period`; `content`: `ContentQuery`, everything after `full:`; `fold`: case folding in place, also used by `index::content`; `filter`: `Filter` (editable kind filter: keyword, extensions, folder), its `Rule`, and `Kinds` (rule bit masks by suffix); `Grammar` = enabled filter keywords + clock. `place`: `Place` (a leading `\` or drive path in the query) `enter`/`origin`/`up` (the query Alt+L makes for a selected folder, the one Alt+H returns to, the parent level).
- `settings`: `Settings` (`Settings::changes`: what an edit touched, compared once by `Shell`, which hands it to `AppWindow`), `History` (recent launches, ranking boosts), `Usage` (`settings/usage.rs`, opens per hour for About), data/cache folders, atomic JSON persistence. `settings/options.rs`: `Suggestions`, `Hotkeys`, `IndexOptions`, `Menu`/`Favorite`/`MenuTool` (the main menu items, commands by builtin or by name, kept on rename and dropped on delete), `Opener`, `Api`; `settings/shortcut.rs`: `Shortcut` (parse, display, GPUI keystroke; stored by US key position, the recorder translates the layout's character with `platform::layout_key`); `settings/tools.rs`: `ActionSpec`, `CommandSpec`, `WebSearch`, `Program`, `Scope` with built-ins and `complete` for old files.
- `i18n`, `theme`, `input` (single-line `TextInput` with IME), `assets` (embedded SVG icons, one standard: a shape on the 24-unit grid inside the shared `HEADER`, stroke 1.6, round caps and joins, `crispEdges`; no transforms, no per-icon stroke widths; a straight segment only where the icon really has a straight edge, since every one becomes a pixel-fitting stem): logic/widgets, no system access.
- `platform`: the only Windows adapter besides `index::ntfs`. Exposes project types (`Event`, `Host`, `HostKind`, `Anchor`, `IconSource`), never `HWND`/`RECT`.
  - `watch`: the watch thread, configured by `Watching` (triggers, bindings, hotkeys, menu clicks, disabled apps). Low-level keyboard hook (double Ctrl, typing in Explorer/dialog file lists, Explorer-scope chords), WinEvent hooks (foreground always; move, destroy, hide and minimize only while there is a host, `watch/hooks.rs`: system-wide location changes include every cursor move and caret blink of every program), global hotkeys (`RegisterHotKey`, paused while a shortcut is recorded), fullscreen guard, hidden window for tray, popups and single-instance toggle. Pure decisions beside it: `watch/tap.rs` (`CtrlTap`), `watch/chord.rs` (`Chords`), `watch/mouse.rs` (`Clicks`; the `WH_MOUSE_LL` hook for the favorites menu runs only while a mouse trigger is on), `watch/spot.rs` (one long-lived thread tells an empty list area from an item: `LVM_HITTEST` through a buffer kept in the desktop process for `SysListView32`, one cached UI Automation call for Explorer views; it starts on the first press of a double click or the wheel press, so the answer is ready by the click, and sends `Event::FolderMenu` with the folder).
  - `window`: placement, show/hide, foreground of the search window; `window/floating.rs`: `Floating`, a frameless popup with its own region, shadow and blur (shared by the card and the menus); `window/card.rs`: the preview card window (no activation, launcher chrome), placed flush right of the panel (left when the screen is short) and following it; `window/menu.rs`: the menu panels (panel 0 activates and remembers the window it took the foreground from, the others don't), placed at the cursor, hanging from the search bar (`MenuAt::Search`, the bar's span in search-window units: the bar's full width, flush on the side away from the dialog, as tall as its items, never flipped but shortened to the screen by whole rows, one shadow cast for bar and menu together; the bar shows neither rows nor footer while joined, and on closing they return under the menu before it hides) or beside their parent row, flipped to stay on screen. `shell`: open, reveal, Explorer navigation (COM `IShellWindows`), dialog navigation (file-name field 1148 + `IDOK`). `files`: run a `Program`, open with, files on the clipboard (copy/cut), recycle, Explorer selection. `context_menu`: the Windows shell context menu, read item by item (with separators) and run on the shell menu thread. `hidden`: the Explorer hidden files setting. `keys`: key names → virtual keys, layout characters → key names (`layout_key`). `icons`: shell icons as BGRA. `tray`: icon and menu.
- `app`: the coordinator (`Shell` entity, kept alive by a global). Opens the search window, routes every `Event`, owns the `AppWindow` handle, publishes the index `Status` global (`IndexChanged` reruns the shown searches at once and then at most every `REFRESH_INTERVAL`, a hidden app window skips it and reruns on show; `IndexCounted` republishes the status, coalesced, without rerunning searches), saves `Settings` (GPUI global, observed), rebinds action keys and applies theme/language/triggers/hotkeys/tray/index options. `app/transition.rs`: `Transition`, the search bar growing into the Vestigo window (expand and settings buttons, whenever the user can't see the window: hidden, minimized or mostly covered by other programs' windows, `platform::app_window_in_sight`, `window/sight.rs`; a window in sight just comes forward) in a click-through transparent overlay (`platform::attach_transition`): the bar's content dissolves into its plain shape while the shape widens evenly into the window, every edge, corner radius and color going from the bar's to the window's along the minimum-jerk profile (`transition/curve.rs`: symmetric bell-shaped speed, no kick, no overshoot); shadow layers go pair by pair from the bar's to the window's (`paint_morph_shadow`, a layer without a pair fades, a maximized window has none). One shadow at a time: `begin_transition` hides the bar's as the overlay appears, the window comes forward with its shadow at alpha 0 (`Reveal` in `platform/window/reveal.rs`, the one state of the show: held, asked, under the shape, shown; also in a plain reveal, so the shadow never shows before the window), the overlay's stays whole while its surface dissolves, and `end_transition` swaps it for the window's in one composition. A translucent end keeps the total opacity while it hands over (`curve::beneath`, `platform::veil_panel`, `platform::veil_app_window`). A frosted end (blur under a translucent window, `Chrome::frosted`) has no transition: the window just comes forward. Each step paints the overlay synchronously (`platform::paint_transition`): once the translucent search bar hides, Windows stops sending the overlay `WM_PAINT` on its own, and the shape froze at the bar. The overlay is never `WS_EX_TRANSPARENT` (the pointer passes through `HTTRANSPARENT`, to Vestigo's windows only): Windows paints such a window, even on `RDW_UPDATENOW`, only after the windows of its thread beneath it, and the Vestigo window under it holds a pending repaint, so the shape froze once the window appeared. The first frame is exactly the bar and the last exactly the window; `platform::hold_app_window` keeps the window's own reveal waiting until the shape rests on it, then the overlay dissolves into the window. Kept deliberately plain: liquid variants (drops, necks, rounding in flight, springs) were tried and dropped; `app/menu.rs`: the favorites menu (favorites with folder contents, recent and open folders, folder tools, commands); `app/api.rs`: the local HTTP API (`GET /api/v1/search`, own thread, answers only `127.0.0.1`/`localhost` hosts).
- `launcher`: the search window (`Launcher` entity): modes, docking, search. `launcher/mode.rs`: `Mode` and its per-mode behaviour. `launcher/tools.rs`: the actions menu, hotkey actions, command and web rows (`tools/menu.rs`: `Menu`, its levels and what they list, pure and tested). `launcher/view.rs`: rendering only, `impl Render for Launcher` kept outside `launcher.rs`. `launcher/folders.rs` (+ `view/folders.rs`): the favorites and recent-folders buttons of the bar under a dialog (Ctrl+B, Ctrl+R), their menus anchored by `view::folder_menu_at` from the same metrics the view uses; `launcher/card.rs`: `Card`, the preview card beside the free search window (its own no-activate popup window, opened by `app` at start; `Launcher::sync_card` feeds it from `observe_self` and card observations and shows it with `platform::place_card` at once (a loading preview is a complete frame); on a non-file row it keeps the last file). Asks for the big window by emitting `Expand`.

the root opens at the cursor or at a search bar button, `MenuAt::Search`, and remembers which, so the button lights up while its menu is open and a press that closed it doesn't reopen it; the root takes the chrome its opener gives: a search bar menu wears the bar's chrome with only its far corners rounded and a divider at the seam, while the bar squares its own corners there and drops its shadow, so the two read as one panel; Key bindings go through `ui::binding` (GPUI key equivalents, so digits and punctuation match by key position in any layout); `app` rebinds them on every keyboard layout change.
- `main.rs`: entry point (logging, elevation, single instance, index start, settings/history globals), then `app::start`.
- Direction: `app → launcher, app_window → ui → index, search, settings, i18n, theme, input, platform`. `launcher` and `app_window` never import each other or `app`; `index` and `search` never import `launcher` or `platform`; `platform` never imports `launcher`. Reverse dependency = design error.
- Win32/COM, `unsafe`, `HWND` only in `platform/`, `index/ntfs.rs` and `main.rs`.
- App icon: `resources/icon.svg` (32 px and up) and `resources/icon-small.svg` (16-24 px, bolder, full-bleed tile) are the source; `resources/icon.ico` (16, 20, 24, 32, 40, 48, 64, 96, 128, 256 px) is rendered from them with resvg and embedded by `build.rs` (`resources/app.rc`, icon resource 1, plus version info). GPUI uses resource 1 for every window; the tray loads it at the small-icon size. Change the SVGs → regenerate the ICO.

### Threads and events
- Other threads (watch thread, index threads) reach the UI only through `platform::send(Event)`; `Shell::handle` is the single place that routes them. Search-window signals are `SearchEvent` (`Event::Search`) and land in `Launcher::handle`. New external signal = new variant + a `handle` arm.
- Hook and window procedures (`extern "system"`) must be fast, never block, never panic (a panic there aborts the process). Their state is a `thread_local` `RefCell` reached through `with_state` (`try_borrow_mut`, re-entrancy safe).
- Low-level keyboard hook: ignore injected input (`LLKHF_INJECTED`); swallow a key only when Vestigo takes it over (typed into a host file list); never touch keys with Ctrl/Alt/Win held.

### State and GPUI
- Visibility: the launcher is visible only while it is the foreground window. `platform::show` reports whether activation worked (a zero mouse `SendInput` lifts the foreground lock); if not, the launcher hides. Losing activation hides it and opens `TOGGLE_GRACE`, so the tray click that caused it doesn't reopen it. Docked to a dialog it stays visible without focus.
- Impossible states unrepresentable: `mode: Option<Mode>` (None = hidden; `Mode::Launcher`, `Mode::Dialog(Host, Side)` or `Mode::Explorer(Host)`, the desktop being an Explorer-like host; per-mode behaviour lives in `Mode` methods and `view::metrics`/`growth`), `Listing` for what the list shows. No `bool` flags beside a tag.
- `render` never mutates the model. Reactions go in the mutating method or a subscription (`subscribe`, `observe_window_activation`, `observe_window_appearance`).
- Calls that can re-enter a wndproc (`platform::place`/`show`/`hide`, `focus_host`, `ShellExecute`, COM navigation, dialog messages) never run inside a GPUI update: they go through `cx.spawn(async move |_, _| …)` like `Launcher::place` and `Launcher::perform`. `ui::perform` runs a command after what was queued before it, on its own short-lived STA thread (`platform::on_shell_thread`: a slow disk, a UAC prompt or a modal shell dialog never holds the interface); only `Drag` (a modal loop that needs the interface thread) and `Focus` stay on the interface thread. Calling them directly from a handler panics on the re-borrowed `App`.
- Layout is computed, not measured: `view::layout(mode, rows)` from the same `Metrics` the view renders with. Change one → change the other; any new fixed-height section must be added to both.
- Async:
  - Blocking work never on the UI thread: search, icon loading and disk scans go to `cx.background_spawn` or the index threads. Small JSON saves of settings/history are the exception.
  - Cancellable work → `Option<Task<()>>` field (`search`; `Launcher::filling` is whatever fills the list next: search, suggestions, shell menu, the latest wins); replacing it drops the stale task. `detach()` only for fire-and-forget (placement, shell commands, icon batches).
  - `cx.spawn` captures `WeakEntity`; apply via `this.update`; entity gone → exit quietly.
- No flicker: the window never changes size while it is open in one mode. It is as tall as `MAX_ROWS` need; the view draws a panel of the current height at the growth edge and fills the rest with the panel background, so every frame is one atomic GPUI present (a window resize lands in DWM before the matching frame and shows a stale or empty strip). The window region (`SetWindowRgn`, rounded by the theme's corners) cuts the window to the panel and limits clicks to it; the filled rest shows only when a frame lands before its region, so it never reads as a hole. DWM applies window geometry (region, backdrop size) about a frame after a GPUI present, so region and blur backdrop change together, never deferred, in the order that keeps the blur inside the visible panel: growing, region first; shrinking, backdrop first. The shadow window follows the panel: it shrinks before the frame, grows after it, and is clear under the panel. `platform::place`/`show` paint the frame synchronously; while a new search runs, keep the previous hits on screen; icons fall back to a same-size SVG until loaded.
- Shared index state is `Arc<RwLock<Volume>>` because index threads own writes; UI state belongs in GPUI entities, never `Arc<Mutex>`/`Rc<RefCell>`.

### Performance
- Hot path is `Volume::find`: no allocation per node, matching on the lowercase arena with prebuilt `memmem` finders, parallel over chunks. A letter mask per node (`Volume::letters`, `search::alphabet`, a parallel array) drops names that lack a letter of the query (`Query::letters`) before the name is read; typo-tolerant nodes skip it. Full paths, depth and context scoring only for the shortlist (`SHORTLIST`); path terms are checked on a lowercase path assembled from the arena into reused buffers. Facet counting runs over every match: per match one `Kinds::of` lookup, no allocation, parallel chunks.
- Node layout stays compact (`Node` ~20 bytes); don't add per-node heap data.
- Any change to `index`, `search` or `cache` that can affect scan, cache load/save or search speed → run the speed test and report before/after (build the base commit in a separate worktree for the "before"). Reference on the dev machine (1.1M entries on `C:`): MFT scan ~2.3 s, cache load ~0.07 s (~0.09 s with the Start Menu fill), cache save ~0.05 s, search ~3-5 ms. Changes to `index::content` → run `content_speed` the same way.

### Design system
Looks are one of the two pillars of Vestigo (with speed). A screen that is off by a pixel, blurry at 125 %, or aligned differently from its neighbour is a bug, not polish. The rules below are enforced where a machine can enforce them; the rest is checked by eye on screenshots (see Agent UI checks).

**Tokens (`src/ui/tokens.rs`) are the only source of sizes; the theme is the only source of everything else.**
- Lengths are written in px at 100 % and rendered in rem: `theme::rem(TOKEN)` in layout, `theme::pixels(TOKEN, window)` in paint code. Each window's rem size comes from `ui::fit_rem` (theme `zoom` × the scale setting, rounded by `theme::zoom_at` so the 4 px grid stays on whole device pixels). Never `px(TOKEN)` for a layout length.
- Every layout length (size, padding, gap, line height, band height) is a multiple of 4 px, so at 100/125/150/175/200 % every edge lands on a whole device pixel. Enforced by tests: `ui::assert_whole_pixels` in each view's tests, `interface_constants_sit_on_the_grid` (every `f32` constant in `ui`, `launcher`, `app_window` must be on the grid; only names ending in `_SIZE` font size, `_SHARE` flex ratio, `_EPSILON`, `_DEVICE` device-pixel count, `RADIUS` are exempt) and `layout_lengths_are_named_constants` (no numeric literal inside `px(…)` or `rem(…)` except `0`).
- Shared scale: type `NAME` 14/20 (names, labels, nav), `DETAIL` 12/16 (paths, hints, footer, section titles, controls), `TITLE` 18/24 (query, page titles); `INSET` 8 (pane edge → row fill), `INDENT` 8 (row fill → content), `GUTTER` 16 (the one content edge); `TOP_BAR` 56 (query / page title band), `FOOTER` 40 (status band); `CONTROL` 32 (buttons, dropdowns), toggle track 40×24. Radii are theme values (`theme.radius.large` rows/controls, `small` chips/menu options, `toggle`). A view constant exists only for something specific to that view (column widths, sidebar width) and still sits on the grid.
- Always set an explicit line height from the scale next to a text size. Never multiply a font size (18 × 1.4 = 25.2 lands between pixels).

**Primitives (`src/ui/widgets.rs`) — use them, never hand-roll an equivalent.**
- Inside a frame, spacing is measured from the line's inner edge: the frame line sits inside the box, so the gaps between fills inside a frame shrink by that pixel to match (dropdown menu: padding `FILL_GAP`, gap `FILL_GAP` − `device_pixels(1)`). Equalize toward the smaller gap, never by padding the frame out.
- Fills never touch: elements that can be filled (selected, hover) and sit next to each other keep `FILL_GAP` (4) between them (nav items, menu options), so a hover fill never merges with a selected one.
- Hairlines: `divider(Edge, theme)` (always the `divider` token) and the private `frame` inside widgets (always `border`); the color comes from the widget, not the caller, so a role can't be mixed up. Both are exactly one device pixel, snapped to the device grid, painted over the edge and taking no layout space. GPUI borders are banned by clippy (`Styled::border_color` in `clippy.toml`): a 1 logical px border is 1.25 px at 125 % and blurs.
- A filled shape with a frame (color samples, chips, swatches) is one quad: fill and frame painted together (`widgets/color.rs::sample`), snapped to the device grid. Never a `bg` fill plus an overlaid `frame`: their separate anti-aliasing leaves a jagged fringe on rounded edges against contrasting colors. A hover variant swaps the whole quad (two layers toggled by `group_hover` opacity), never stacks a second frame on top.
- Disclosure rows (folds) open on a click anywhere in the row: `settings_page::fold_row` with the `ui::disclosure` chevron, which lights up when the row is hovered.
- Anything whose edge is visible (fill or frame) either has a fixed width from tokens (`button` = `BUTTON_WIDTH`, sliders and setting fields = `CONTROL_WIDTH`, text keys = `KEY_WIDE`), a measured width rounded up to the 4 px grid (dropdowns: `CONTROL_WIDTH`, wider only when their widest option needs it, at most `DROPDOWN_MAX`; trigger and menu share it; labels fade only when that cap cuts them), or draws its edge with the snapped `frame`. A fill whose width comes straight from text measurement sits at fractional pixels and blurs.
- Text that can overflow goes through `faded`, which shows a `Tip` with the full text when it is clipped (in the launcher limited to the panel, `Tip::inside`); scroll areas get `glide` (smooth wheel scrolling; the row selected by the pointer glides into view, keys jump to whole rows at once) and `edge_fades`, except result lists, which have no fades. `truncate`, `text_ellipsis`, `line_clamp` are banned by clippy (a cut text fades through `faded` instead).
- `hint_chip` for key hints, `icon_button` for glyph buttons, `button`, `toggle`, `slider`, `swatch`/`color_button` (`widgets/color.rs`) and `dropdown` (every choice between options, like theme, scale and language) for settings controls. A new kind of control is added to `widgets.rs` with token sizes first, then used.
- Colors only from `Theme` groups: `gpui::rgb`/`rgba`/`hsla`/`black`/`white` are banned by clippy. No in-window shadows (banned); window shadows are their own windows.
- Themes (`src/theme.rs`, `theme/catalog.rs`, `theme/edit.rs`): JSON = `resources/themes/base.json` (the design system: every element group mapped to palette roles, radii, font, zoom, window chrome) ⊕ optional `"base": "light" | "dark"` ⊕ the theme's own file; role names in groups are replaced by palette colors, then every section is parsed strictly (unknown field = visible error in settings). Built-in, inside the app and never deletable (`Origin` in `catalog.rs`): `light.json`, `dark.json` and the examples `catppuccin-mocha.json`, `dracula.json`, `soft-sand.json`; all opaque without blur, with the same soft shadow (the `shadow` role at alpha `1f`). The user's themes are files in `%APPDATA%\Vestigo\themes`, deleted from Appearance to the Recycle Bin. Older versions copied two examples there: `settings::retire_themes` removes those copies when untouched (`resources/themes/retired`), an edited one stays and is reported as a taken name. Element colors must be opaque: a translucent fill under a fade blends twice and shows a box. Transparency is per window (`windows.*.opacity` → layered window alpha), blur is a separate backdrop window under the panel or app window (`window/backdrop.rs`: the accent blur ignores the window region of a DirectComposition window and would be dimmed by its alpha). The backdrop has no redirection surface and no DWM transitions, so its geometry lands without waiting for a repaint or an animation. New visual element → a field in its group (or a new group) in `theme.rs` and `base.json`, mapped to a role, plus its key in `edit::GROUPS` and its name in `theme_fields`/`theme_groups` (tests check both). The editor's edits are a JSON overlay per theme id (`ThemeEdits`), merged over the theme's own layers by `Entry::sheet`/`Catalog::resolve`; an edit equal to the original value is dropped.
- Text-position-dependent paint (caret, selection) snaps to device pixels with `theme::snap`; device-pixel thicknesses come from `theme::device_pixels`.
- A transparent color is always a token with `.opacity(0.)`, never transparent black or white (banned by clippy): GPUI blends anti-aliased edges in straight, not premultiplied, alpha, so a rounded frame filled with transparent black gets dark corners and a fade from transparent black darkens what it fades into.

**Alignment.**
- One left edge per pane: `GUTTER` from the pane edge for titles, query text, column headers, row icons, settings labels, footer status. Right edges mirror it: controls, footer hints and the expand glyph end `GUTTER` from the right.
- Bands line up across a window: the sidebar runs the full window height (the "Vestigo" title sits in its top band), its first item is centred on the `TOP_BAR` band and its bottom item on the status band. Both app window pages share the same top band (query or page title).
- Dividers are rare: a hairline only where two different kinds of content meet and spacing alone can't separate them. Today that is the sidebar edge, the line under the top band (query or page title), the lines between rows of one settings section and the line above the file properties in the preview. No line under a title bar, a table header or a section title, none above a footer or status bar, none around a single item. Adding a divider needs a reason that fits this rule.
- Icon buttons align by their glyph, not their hit box (`icon_button` has a negative margin of its padding), so a glyph's edge sits exactly on the content edge.
- Launcher rows end `trailing` from the edge, a bit more than `indent`, because shell icons leave a transparent margin inside their box: the icon art and the `Ctrl+N` hint then sit at the same visual distance from the sides. Row height leaves the same visual space above and below the text as there is beside it (56 launcher, 36 docked and table rows; the actions list is denser, 40 launcher, with a 20 px glyph per built-in action and the bolt for custom ones). No search icon: the placeholder and the caret say what the field is.
- Table columns: header labels and cells share `columns`/`column_cell`, so a label always starts or ends exactly where its values do; numbers are right-aligned (`Column::align`). A state mark (sort arrow) goes on the side away from the column's anchored edge, so showing it never moves the label.

**Style.**
- Vercel style for the built-in themes: monochrome, hairline borders, generous spacing, no accent colors, pure black and pure white. Every built-in and example theme must look right.
- Font: `theme::FONT`. Match highlight = the `matched` color only, same weight as the name (a bolder run widens the text and shifts it as the query changes), base text `theme.text`, secondary `muted`/`faint`. Section titles are `DETAIL` semibold `muted`.
- Tokens by role: `selected` result row fill, current nav item, chosen menu option; `hover` the fill under the pointer for ghost controls (nav items, menu options, dropdowns, buttons, caption buttons); `divider` structural hairlines (dimmer, so lines recede behind content); `border` frames of controls and key chips; `muted` paths, status, hints, nav labels; `faint` icons, placeholders, shortcuts, key glyphs, disabled text; `selection` selected query text; `track` an off toggle. New visual role → new token, else reuse the nearest existing one.
- Every clickable element answers the pointer, built into its `ui` widget so it can't be forgotten: ghost controls get the `hover` fill (and `text` color), glyph buttons switch the glyph to `text`, sortable column headers switch to `text`, result rows select on hover. Toggles show only the pointer cursor: their shape already says they are clickable. A pointer cursor only where a click does something: the current nav item and disabled buttons get neither hover nor pointer.
- Pointer targets (anything with a hover style, a click or pointer-driven selection) call `block_mouse_except_scroll()`: GPUI's hit test counts both edges of a box, so two touching targets would share their edge pixel and both light up and take the click. The topmost target wins; parents still scroll.
- `track_focus` never on an element that covers a drag area (caption bar, sidebar title): GPUI focuses it on mouse down and calls `prevent_default`, which marks the caption click handled, so Windows never starts the move. The app window tracks its focus on the page area below the caption.
- Input is painted at once: the subclass procs forward input messages through `window/prompt.rs`, and when a view notified while GPUI handled one (`ui::paint_changes` on every root view, `ui::paint_changes_of` on every text input), the frame is painted synchronously instead of waiting for GPUI's vsync tick. Not while a launcher placement is pending (`platform::note_placing`): `platform::place` (a posted task, always ahead of `WM_PAINT`) paints that frame together with the new region, so a resize never shows the new panel inside the old region.
- Pointer: hovering a result row selects it (one highlight, no separate hover state); placement resets the pointer so a window moving under a still cursor selects nothing.
- Docking: under a dialog the query row sits flush below the dialog frame and the list grows down; when the full window doesn't fit below (`platform::fits_below`), it sits flush above the dialog, the list grows up and the theme's dialog corners flip vertically. In Explorer the window sits flush in the bottom-right corner of the client area (inside the frame), on the desktop in the bottom-right corner of the work area, and the list grows up. All come from `growth(mode)` and `Mode::anchor`.
- Icons are drawn 1:1 at the device-pixel size of their box (`IconKey { source, pixels }`), reloaded when the scale changes. Launcher icons are 32, docked and table 16. `IShellItemImageFactory` scales icons crudely (aliased or blurry at non-native sizes, crude small bitmaps even at native ones), so `ui::icons` fetches the 256 px image and shrinks it itself (Lanczos3 in premultiplied `f32`); only at 16 px and below the icon's own hand-drawn bitmap wins. Shell bitmaps are straight alpha: never unpremultiply them. Packaged apps (`shell:AppsFolder` items, shortcuts with a packaged AppUserModelID) get a plated tile from the shell (tiny logo on the accent color), so `platform/icons/package.rs` reads the logo from the package itself (`Tile.SmallLogoPath` under the install path): the MRT file nearest the size, `altform-unplated` first; an unplated white glyph is replaced by the plated asset on the tile color, its glyph centred at two thirds of the tile like Windows draws it; no usable file → the shell's image at the exact size.
- Icons show at once, never as a placeholder for something seen before: `Icons` is saved to `%LOCALAPPDATA%\Vestigo\icons.bin` (the 1024 most recently used, written 2 s after a change) and restored at start (~1 ms); a restored icon is shown as is and checked once per session in the background, replaced only if its pixels changed. At start the Start Menu shortcuts and the history get their launcher-size icons in the background, so apps show icons even on their first search.
- `uniform_list`: pad its parent, never the list (GPUI 0.2.2 applied the list's own top padding twice).
- Search window: no border. `platform::attach` makes the whole window client area (subclassed `WM_NCCALCSIZE`; GPUI otherwise leaves an invisible resize frame that DWM outlines) and turns off DWM non-client rendering. No DWM frame in the client area (`DwmExtendFrameIntoClientArea`): DWM paints it white wherever a frame is late, e.g. while the window grows. The shadow is its own window (`window/shadow.rs`, one `Shadow` per window, the app window has one too): layered, click-through, kept right below its window, painted on the CPU as an exact Gaussian blur of the rounded window shape and repainted only when the size, scale or look changes. Its layers come from the theme (`windows.*.shadow`, CSS `box-shadow` semantics: color, opacity, x, y, blur, spread; an empty list means no shadow); the base theme turns it off under a dialog, where the bar reads as part of it. The app window always has a window region while not maximized, so DWM draws no shadow of its own.
 Corners come from the theme (`windows.*.corners`, square by default): the window region always turns off Windows 11 rounding.
 Hairlines only separate sections inside.
- App window: a normal resizable window without any system frame or outline: `platform::attach_app_window` makes the whole window client area (subclassed `WM_NCCALCSIZE`, inset by the frame only while maximized), answers resize hit tests on its edges (`SM_CXSIZEFRAME` band) and clears the Windows 11 border color. Its own title area: the whole top band (sidebar title and caption bar) drags, caption buttons 48 × 40 with the `hover` fill. A double click on the caption of the maximized window restores it to its default size, centred in the work area of its monitor, in one placement (`restore_default`), not to its previous size. The subclass answers these hit tests from the point in the message and `view::CAPTION_AREAS` (the same constants the view lays out with), never GPUI's `WindowControlArea`: GPUI hit-tests the last known mouse position, a move behind, so client and caption alternate at the edges and the cursor and hover fills flicker. The hover reset on `WM_MOUSELEAVE`/`WM_NCMOUSELEAVE` (`window/prompt.rs`) runs only when the cursor really left the window, not when it crosses between client and caption.

### Data and persistence
- Atomic writes: temp file → `rename` (`settings::save`, `cache::save`).
- `settings.json`, `history.json`, `usage.json` (`%APPDATA%\Vestigo`) are a contract with existing installs: new field `#[serde(default)]`, rename `#[serde(alias)]`, removal or meaning change → migration + test reading the old file.
- Damaged JSON is never silently overwritten: keep a `*.broken.json` copy (`settings::load`).
- Index cache format change → bump `MAGIC` in `index/cache.rs`; an old cache is then rejected and rescanned, no migration. The same for the icon cache (`ui/icons/disk.rs`): an old file restores nothing.
- Logs: `%APPDATA%\Vestigo\logs`.
- The old name: on start `settings::adopt_legacy_data`/`adopt_legacy_cache` move `%APPDATA%\sfs` and `%LOCALAPPDATA%\sfs` (or copy settings and history if the folder is locked) unless the new folder exists; after a data move `autostart::adopt_legacy` replaces the `sfs` task with `Vestigo`. Keep the `sfs` names only there.

### Errors
- `anyhow::Result` in app; `.context(...)` where failure would be unclear. Failed user actions are logged (`log::warn!`); add a visible error state before relying on users reading logs.
- Outside tests never: `unwrap`, `expect`, `panic!`, `todo!`, `unimplemented!`, `unreachable!`, `dbg!`, out-of-bounds-capable indexing. Use `?`, `let … else`, `get`. Clippy enforces (`[lints.clippy]` in `Cargo.toml`; `clippy.toml` allows in tests).
- Don't swallow errors. `let _ =`/`.ok()` only for truly optional work (cleanup, best-effort Win32 calls whose failure changes nothing); else `log::warn!`.

### Types and API
- New concept = new type: enum instead of string or special-meaning `bool` (`HostKind`, `Anchor`, `Command`, `ThemeChoice`).
- Variant-dependent properties in one place (`Mode::anchor`, `metrics(mode)`), not parallel `match`es. Matches over own enums: exhaustive, no `_ =>`.
- Minimal visibility: private → `pub(super)`/`pub(crate)`. Fields of invariant-holding types private (`Volume`, `Query`).
- Magic numbers → named module constants.
- Hot paths (`render`, search scan): no needless clones; borrow.
- No speculative abstractions: no single-impl traits, no unused params/flags/settings.
- New dependency only if std and existing crates have no reasonable alternative; name it in the report.

### Structure
- File > ~600 lines or function > ~60 lines → split by meaning. Submodule beside its code (`mod x;` + `x.rs`, tests in `x/tests.rs`).
- Pattern in 3+ places → shared helper.
- rustfmt via `rustfmt.toml` (`max_width = 120`, `use_small_heuristics = "Max"`). No hand formatting; don't edit `rustfmt.toml` to fit.
- Fix clippy findings in code. Silence only proven false positives, narrowest item, `#[expect(clippy::lint, reason = "why")]`. Never crate-wide `allow`, reasonless `#[allow(...)]`.

## Tests
Tests catch bugs; not for count or green. You decide by these rules and write/update yourself. "No test needed" is normal.

Write a test only if it can catch a real bug. Must fail on a wrong implementation.
- Bug fix: write the test first, confirm it fails on old code, then fix.
- New logic: mentally check a breakage (inverted condition, off-by-one, forgotten update) fails it.

Hunt bugs: empty/blank queries; Cyrillic and other non-ASCII names (case folding changes byte lengths); spaces, `/` and `\` in queries; children arriving before parents; deletes and renames replayed twice; orphans; truncated or foreign cache files.

By change kind:
- **Index/search/cache/history logic**: test in the module's `tests.rs` (`index/tests.rs`, `search/tests.rs`). Build volumes with `Builder`/`Volume::insert`, search through `Index`. Extend an existing covering test instead of duplicating.
- **Watch-thread logic**: keep decisions in pure functions/structs (`CtrlTap`) and test those; the Win32 glue stays thin.
- **New UI strings**: the field in `Strings` (`src/i18n.rs`), values in both `i18n/en.rs` and `i18n/ru.rs`.
- **Win32 integration** (hooks, Explorer/dialog navigation, placement, tray, icons): no automated test exists; name it as untested in the report and describe how the user can check it.
- **No test**: styling without new behavior; behavior-preserving refactors.

How:
- Test the contract (what the user sees/gets), not internals. One behavior per test, descriptive name.
- Full isolation: no real windows, input, registry or drives; files only in temp folders with unique names, removed afterwards. Real-drive tests only as `#[ignore]` with a reason.
- Expected values independent: explicit constants, never computed by the code under test.
- Failing test = found bug by default. Change an expectation only if the task changes that behavior; unclear → ask the user.
- Forbidden for green: deleting tests/assertions, weakening conditions, `#[ignore]` on a failing test.
- Report: one line on tests added/changed and what they catch (or why none); risky untested parts; each changed expectation, before → after, and why.

## Agent UI checks
The user works at this computer concurrently and Vestigo hooks global input, so runs affect them.
- The sandbox runs only when the user directly asks for it in this task. Without that, never start it; if a sandbox check seems worth it (a visible change, possible flicker, docking), offer it in one line at the end of the report: what would be checked and why. The rules below describe how to check once the user asked.
- Every check that opens a window, takes a screenshot or a video, or needs input runs in the Windows Sandbox (below), never on the user's desktop. That includes test dialogs (`OpenFileDialog`, `FolderBrowserDialog`), inspecting other windows' controls, opening Vestigo's own windows to look at them and `scripts\screenshot.ps1`. On the host the agent only builds and runs tests (and quits or relaunches the user's instance when they allowed it). Something the sandbox can't show (pixel sharpness at the user's scale, the user's own apps) → name it for the user to check instead of opening it on their desktop.
- A requested check of a visible change (layout, widget, token, string length) uses sandbox screenshots: `App` starts Vestigo, `App '--window'` / `App '--settings'` open the app window and settings, `Shot name` saves the screen. Shoot the second theme only when the change can look different there (colors, theme fields, contrast, anything painted from theme values); a change of sizes, positions or logic is the same in both. For the other theme, write `{"theme":"dark"}` to the VM's `%APPDATA%\Vestigo\settings.json` without a BOM (`[IO.File]::WriteAllText`; Windows PowerShell's `Set-Content -Encoding UTF8` adds one, the file then fails to parse and Vestigo starts with defaults), then `Deploy` and `App`.
- Look at the shots at 100 % and zoomed (crop + nearest-neighbour scale ×4): hairlines one pixel, every left edge on the gutter, right edges mirrored, text centred in its band, same-role elements the same height, nothing clipped hard, no stray gaps. Write down what you checked.
- Docked mode: open a standard file dialog in the VM from a separate process (a PowerShell `System.Windows.Forms.OpenFileDialog` or `FolderBrowserDialog` in `-STA`), shoot, then stop that process.
- Never send synthetic input (`SendInput`, `keybd_event`, `SetCursorPos`) or click on the user's desktop, and never message their other windows to "test" the Explorer/dialog integration.
- Don't keep screenshots in the repo.

### Isolated e2e (Windows Sandbox)
Real input, screenshots and video without touching the user's desktop: Vestigo runs in a hidden Windows Sandbox VM (feature `Containers-DisposableClientVM`, software WARP, no network). The only place for UI checks; there Vestigo hooks only the VM.
- `scripts\e2e\start.ps1` builds the sandbox config, starts the VM on its own hidden desktop (no window, focus or input on the user's desktop; the guest's audio service is stopped, so no sounds) and waits until the agent is ready (`-Stop` closes it). Work folder `%TEMP%\vestigo-e2e`, outputs in `out\`. Uses the existing `target\debug\vestigo.exe` (run `cargo build` first).
- `scripts\e2e\send.ps1` runs PowerShell from stdin in the VM and prints the output. It waits 100 s (`-TimeoutSeconds`); after a timeout the script keeps running in the VM and the next one queues behind it, so check `Get-Process vestigo` start times before trusting shots. Helpers: `Deploy` (stops Vestigo and copies the freshly built exe; it does not start it, `App` does), `App [args]` (the first `App` starts the instance, later calls like `App '--window'` signal it), `Keys` (SendKeys), `Click x y`, `Shot name` (PNG), `Rec name seconds` (mp4).
- Never move the real cursor in the VM (`SetCursorPos`, `mouse_event`, `SendInput`, `Cursor.Position`): Windows Sandbox mirrors the guest cursor onto the host, so it moves the user's own cursor. Pointer input only through `Click` (posted window messages).
- The sandbox screen is small and its D3D is WARP: check layout and behavior there, not pixel sharpness or speed. The index there is a tiny drive: speed numbers still come from the real `C:` test.
- Debug GPUI compiles shaders from its crate sources at runtime; `start.ps1` maps `vendor/gpui_windows` into the VM at the same path.
